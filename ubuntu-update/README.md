# Обновление Ubuntu — памятка

> Эта папка — личная шпаргалка по обновлению системы Ubuntu.
> Создана из-за сообщения **«информация об обновлении устарела»**.

---

## Что значит «информация об обновлении устарела»

Это сообщение от «Программы обновления» (Software Updater / GNOME Software).
Оно означает, что **локальные списки пакетов apt устарели** — система давно
не скачивала с серверов свежий перечень доступных обновлений.

Причины обычно простые:
- давно не запускалось обновление;
- были временные проблемы с сетью;
- кэш пакетов «протух».

Лечится обновлением списков пакетов (`apt update`).

---

## Быстрое решение (терминал) ✅

Открой терминал (`Ctrl+Alt+T`) и выполни:

```bash
sudo apt update        # обновить списки пакетов (это и убирает сообщение)
sudo apt upgrade -y    # установить доступные обновления
```

После этого сообщение «информация об обновлении устарела» пропадёт.

Полное обновление (включая пакеты, требующие смены зависимостей):

```bash
sudo apt full-upgrade -y
```

---

## Решение через интерфейс (без терминала)

1. Открой приложение **«Программа обновления»** (Software Updater).
2. Нажми **«Обновить»** / «Проверить наличие обновлений».
3. Если предложит установить обновления — нажми **«Установить сейчас»**.
4. При необходимости перезагрузи компьютер.

В GNOME можно также: **«Приложения» (App Center / Software)** → вкладка
**«Обновления»** → «Обновить».

---

## Очистка после обновления (по желанию)

```bash
sudo apt autoremove -y   # удалить ненужные старые зависимости
sudo apt autoclean       # подчистить устаревший кэш .deb
```

## Если появляются ошибки при `apt update`

### 1. «Не удалось получить» / repository ... no longer has a Release file
Сломан какой-то сторонний репозиторий (PPA). Посмотреть и при необходимости отключить:

```bash
ls /etc/apt/sources.list.d/        # список подключённых репозиториев
sudo nano /etc/apt/sources.list.d/имя-файла.list   # закомментировать строку через #
```

### 2. «Could not get lock /var/lib/dpkg/lock»
Уже запущено другое обновление (например, авто-обновление в фоне). Подожди пару
минут или:

```bash
sudo killall apt apt-get 2>/dev/null
sudo dpkg --configure -a
sudo apt update
```

### 3. Битые/незавершённые пакеты
```bash
sudo apt --fix-broken install
sudo dpkg --configure -a
```

### 4. Уведомление «репозиторий ... не поддерживает архитектуру i386»
Пример (Google Chrome):
`N: Пропускается ... так как репозиторий «...chrome-stable...» не поддерживает архитектуру «i386»`

Это **не ошибка**, а уведомление: в системе включена 32-битная архитектура,
а репозиторий отдаёт только 64-битные пакеты. На обновления не влияет.
Чтобы убрать — указать репозиторию только `amd64`:

```bash
sudo nano /etc/apt/sources.list.d/google-chrome.list
```

Привести строку к виду (добавить `[arch=amd64]` после `deb`):

```
deb [arch=amd64] https://dl.google.com/linux/chrome-stable/deb/ stable main
```

Сохранить и выполнить `sudo apt update` — уведомление исчезнет.

## Обновление до новой версии Ubuntu (раз в полгода/год)

Это уже переход на новый релиз (например, 24.04 → 24.10), не путать с обычными
обновлениями:

```bash
sudo apt update && sudo apt upgrade -y
sudo do-release-upgrade
```

> ⚠️ Перед переходом на новый релиз желательно сделать резервную копию важных данных.

---

## Полезные проверки

```bash
lsb_release -a              # какая версия Ubuntu установлена
uname -r                   # версия ядра
apt list --upgradable      # какие пакеты можно обновить
```
